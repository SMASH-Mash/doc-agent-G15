# Per-stage design choices (A2 deliverable)

| Stage | Problem statement | Data | Model | Methods | Design | Development | Deployment | MLOps |
|---|---|---|---|---|---|---|---|---|
| 1 Ingest+Enhance | Convert each source PDF into a complete, ordered, pixel-based page set without silently dropping pages, while preserving mathematical stroke information. Enhancement must not damage clean mathematical notation. | Four openly licensed STEM textbook PDFs from Siyavula Grades 11–12 and OpenStax Calculus Volumes 1–2. A1 describes them as born-digital and clean; the corpus is intentionally rasterised so downstream OCR must read pixels rather than the embedded text layer. | No learned model. Deterministic PDF rasterisation with PyMuPDF/pdf2image at 300 DPI. Generative enhancement is out of scope for this corpus. | Render every page as 300 DPI RGB PNG; write deterministic page metadata and hashes; preserve document/page identity. Deskew, denoise, grayscale, binarisation and generative enhancement remain disabled by default because A1 found no scan artefacts requiring them. | Keep ingest as a single-responsibility offline stage. A page-count and file-integrity gate is more valuable than aggressive enhancement here. This costs one rasterisation pass and extra storage, but avoids corrupting fractions, superscripts and thin mathematical strokes. A change to visibly degraded inputs would justify enabling targeted cleanup. | Unit-test page rendering, page count, image readability and manifest creation. Keep DPI, paths and overwrite behaviour in configuration. Validate corpus-level document boundaries before downstream processing. | Run once as a cached offline batch job; never render pages during a student query. Outputs are consumed by layout and OCR. | Version the corpus by source/document manifests and content hashes. Re-ingest when source editions change. Keep raw inputs immutable and derived page images reproducible from the same source/config. |
| 2 Layout | Identify and order prose, headings, formulas, tables and figures so mathematical 2-D structure is not flattened into an incorrect global reading order. | The rasterised textbook pages contain dense mathematics, worked derivations, multi-column exercise layouts, tables and diagrams. A1 specifically identifies superscripts, fractions, aligned derivations and column ordering as difficult visual structures. | `docling-project/docling-layout-heron`, pinned to the repository revision. | Batch page-level detection, score thresholding, bounding-box clamping, overlap deduplication and deterministic recursive reading order. Page headers and footers are ignored according to configuration. | Region detection precedes OCR so OCR can use region type and geometry. The reading-order logic handles full-width blocks and local columns rather than relying on a single global y/x sort. This costs model inference but protects the math-speciality requirement. Revisit ignored header/footer behaviour if citation or page-context needs change. | Use deterministic manifests and unit tests for label mapping, box clamping, overlap handling and reading order. Save optional debug overlays for failed cases. | Run in the offline A2 build with CUDA when available and fall back to configured device behaviour. Persist the region manifest so OCR can resume without rerunning layout. | Pin the Heron revision and store the layout manifest as a reproducible intermediate artifact. Log model revision, threshold, batch size and region counts for each build. |
| 3 OCR | Convert layout-aware page regions into retrieval-safe prose and LaTeX while retaining formulas, tables, derivation order and page provenance. The OCR must be robust to math-heavy layouts and malformed generation. | Layout crops from the STEM textbook pages, with figure regions skipped by configuration. Inputs are the actual page pixels plus region metadata such as kind, bbox, page ID and order. | `docling-project/granite-docling-2stage-258m`, pinned to the repository revision. This is the implemented A2 baseline; the current repository does not contain project-specific OCR fine-tuning. | Region-aware prompting; formula/table/code-specific prompts; adaptive token budgets; bbox-guided crops; one retry for suspicious outputs; repetition-loop detection; duplicate/repetitive-tail repair; Unicode normalisation; LaTeX preservation; resumable canonical JSONL manifest. | OCR output is treated as untrusted extracted text. Every record keeps page, document, bbox, model revision, order, generation mode and quality flags. The design favours faithful mathematical transcription over generic text throughput. The trade-off is higher OCR compute and slower retries in exchange for better handling of notation-heavy pages. | Test label mapping, reading order, prompt geometry, normalisation, repetition repair and error-rate utilities. Use the held-out grading set for actual CER/WER once ground-truth labels are populated. | Run as an offline batch stage. Resume from the canonical OCR manifest to avoid repeating expensive model inference. | Pin the OCR checkpoint revision, persist the canonical OCR manifest, retain quality flags and generated-token counts, and record the exact config used for the build. Hold out evaluation pages from any future tuning. |
| 4 Index | Turn OCR output into stable semantic retrieval units and a persistent vector store while preserving page-level provenance required by the Explainable NFR. | Successful OCR regions from the textbook corpus. Chunks retain `chunk_id`, `doc_id`, `page_ids`, text and source-region information. The structure-aware chunker is configured for 384 estimated tokens, 48-token overlap and 64-token heading context; formulas, tables and code are atomic. | Chunking is deterministic and model-free. Embeddings use `BAAI/bge-m3`, 1024 dimensions, normalized. The vector store uses FAISS `IndexFlatIP`. | Structure-aware chunking; sentence-aware splitting; heading propagation; overlap; atomic preservation for formulas/tables/code; batch embedding; normalized dense vectors; inner-product search; persisted FAISS index plus chunk metadata JSON. | Separate chunking, embedding and storage so each contract is testable independently. Normalized BGE-M3 vectors make inner product equivalent to cosine similarity. `IndexFlatIP` is simple and exact for the current corpus size and avoids introducing ANN approximation error. Reconsider ANN indexing if corpus scale makes exact search too expensive. | Unit-test chunk determinism, heading context, atomic math preservation and overlap. Validate embedding shape, finite values and normalization. Validate index/vector/metadata counts on load. | Build once as an offline artefact. Persist `data/index/index.faiss` and `data/index/chunks.json`; later retrieval reads these artefacts rather than rebuilding them per query. | Keep embedding model/revision and index configuration fixed for a build. Store chunk manifests and index metadata together. A corpus or embedding-model change should trigger a complete re-index and invalidate stale vector artefacts. |
| 0 Frame | A1 framing is already fixed and carried forward: high-school STEM mathematics, math/scientific notation, and Explainable as the primary NFR. | A1 corpus and document-level train/test policy. | A1 planning choices are refined into the implemented A2 stack above. | The mandatory agent evidence-gated re-search policy is implemented in A3, not in the A2 KB build. | A2 stops at the persistent knowledge base. | Keep the A1 form, task configuration and A2 artefacts consistent. | Not an online serving stage in A2. | A1 decisions are the contract that downstream stages must preserve. |
