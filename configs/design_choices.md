| 0 Frame | Given a scanned page-image from our corpus, answer a question grounded in the page's text, with our three choices — domain: High School STEM Education; data speciality: math/scientific notation; primary NFR: explainable (Grounded Explanation Faithfulness Score >= 0.90, 100% citation traceability). Split by document: train = siyavula_gr11 + openstax_calc1, test = siyavula_gr12 + openstax_calc2. | No model at Stage 0 — a deterministic config/task spec, not a learned component. | `configs/task.yaml` + `grading_kit/manifest.yaml` declare the three axes and corpus stats; both are the single source of truth every later stage reads from. | `configs/task.yaml` is the one place the axes are set; nothing downstream re-derives them. | `data.validate.validate()` asserts the corpus meets the declared floor on every real run (not just once at A1), catching a stale/truncated corpus early. | N/A — framing has no runtime deployment. | `grading_kit/manifest.yaml` is the single entry point a grader/teammate reads to reproduce this axis choice. |
| 1 Ingest+Enhance | Turn the 4 source PDFs into a validated, deterministic list of `Page` objects with zero silently-dropped pages, ready for layout+OCR. Success metric: `len(pages) == manifest page count` and `data.validate.validate()` passes on every run. | `scripts/get_data.sh` fetches each book from its publisher's own canonical PDF link (OpenStax's CMS API `pdf_url` field, Siyavula's direct download links) rather than the team's Drive mirror — more stable, matches the handbook's preference. Rasterises at 300dpi RGB into `data/raw/<book_id>/<page_num>.png` + `manifest.jsonl`. Real corpus fetched: 2,521 pages, ~1.1GB rasterised + 111MB source PDFs. | No learned model — the corpus is clean, born-digital PDFs, so `enhance.enabled: false` (A1's own finding: 0/2521 pages needed deskew/denoise/repair). | `ingest/preprocess.py` is a lightweight image-based quality gate (blank/near-uniform-page and corrupt-image detection via PIL `ImageStat`), not classical CV correction, since there is nothing to correct. `data/validate.py` estimates real word count via each PDF's text layer for QC only (never as OCR output for the KB — A1's stated principle). | `ingest/loader.py` adds `image_path_for()`/`doc_id_for()`/`page_num_for()` helpers so downstream stages can resolve a `Region`'s image from just its fixed `page_id` field (contracts.py can't be extended). `dev.max_pages` config knob enables a fast, stratified-across-all-4-books local smoke-test sample without touching any stage's code. | Verified against the real corpus: `load_pages()` + `preprocess.run()` + `validate()` all pass; `data.versioning.snapshot()` hashes `data/raw/` for a reproducibility checksum. | `get_data.sh` is meant to run once, offline, at corpus-prep time (mirrors A1's own committed design) — not at serving time. Made idempotent/self-healing after a real bug (a transient DNS failure lost two books' manifest rows since the manifest was only written once at the end) surfaced during the actual run. | `data/versioning.py::snapshot()` gives a checksum-based re-ingest trigger, matching A1's committed MLOps design. |
| 2 Layout | Detect text/table/figure/heading regions per page so OCR can be targeted and figure regions can be skipped (nothing to OCR in a diagram). Success metric: every page yields >=1 region, verified on the real corpus (0 empty pages). | Same 2,521-page corpus; layout reads the *original* source PDF's structure (text blocks, embedded images, native table finder), not the flat rasterised PNG. | Primary: DocLayout-YOLO (`juliozhao/DocLayout-YOLO-DocStructBench`), a genuinely pretrained, published (2024) document-layout model — the "reproduced pretrained method" for this stage. Installed via an optional pip extra since its transitive dep chain needs a native toolchain unavailable on this Windows dev machine (Linux/CI/Kaggle unaffected). | Fallback (also this machine's tested path, since the extra isn't installed locally): a deterministic PyMuPDF structural detector — `find_tables()` for tables, `get_images()` for figures, font-size heuristic for headings vs body text, with a column-aware merge pass (added after real testing showed PyMuPDF's raw text blocks were far more fragmented — 456 tiny blocks over 20 pages — than the paragraph-scale units Nougat needs). | `vision/layout.py::detect()` tries DocLayout-YOLO first, falls back automatically (`try`/`except ImportError`) — same code path everywhere, no environment-specific branching needed by callers. | Verified on the real corpus (20-page sample): 294 merged text/heading regions + tables + figures, every page covered, no empty pages. | Runs once per corpus build inside `build_knowledge_base()`, offline/batch — same as Stage 1. | N/A this stage (no separate tracked artifact beyond the index built downstream). |
| 3 OCR | Transcribe each non-figure region to text/LaTeX, preserving mathematical notation exactly as printed (A1's committed math-aware requirement — E25 data-speciality gate). Success metric: correct LaTeX reconstruction of subscripts/superscripts/fractions on a math-heavy sample. | Same corpus; OCR reads the rasterised PNG crop for each region (padded 2% to avoid clipping strokes/superscripts at the bbox edge). | Nougat-small (`facebook/nougat-small`) via `transformers`' native `VisionEncoderDecoderModel`/`NougatProcessor` — a genuinely pretrained math-aware vision-language OCR model, exactly A1's committed choice, not a generic OCR baseline. | `vision/ocr.py::Reader` loads the model once (lazy singleton), auto-detects `cuda`/`cpu`. Figure regions are skipped (A1's "high visual dependency" finding: nothing to OCR in a diagram; A3's `read_page`/`enhance_page` tools handle visual context instead). | Verified on real content: `T_{n}=an^{2}+bn+c` correctly reconstructed with proper subscript/superscript LaTeX from an actual Siyavula worked example — directly solving A1's named "superscript/subscript baseline collapse" failure mode. One real failure also observed: a very small/near-empty crop produced a hallucinated "Figure Captions" repetition — a genuine, honestly-reported instance of A1's own predicted "OCR failure & repetition/hallucination" risk. | CPU timing (this dev machine): ~5-8s/region after model warmup, tables slower (up to ~80s) — confirms A1/A2's own reasoning that the real 2,521-page build needs GPU (Kaggle T4x2), local runs are for correctness-checking only via `dev.max_pages`. | Model checkpoint pinned in `configs/config.yaml` (`ocr.model`), swappable to `facebook/nougat-base` for the Kaggle GPU run without any code change. |
| 4 Index | Chunk transcribed text without splitting formulas, embed it, and build a retrievable vector index. Success metric: `index_stats.json` reports a chunk count/dim/coverage that traces back to the actual corpus processed. | Raw per-region OCR chunks, grouped by document in page/region order. | Embedding: `sentence-transformers/all-mpnet-base-v2` (768-dim), a well-established pretrained embedding model — no exotic prompt-prefix requirements, kept simple/coherent for A3's retriever. Vector index: FAISS `IndexHNSWFlat` (cosine via normalized inner product) — genuinely reproduces Malkov & Yashunin's published HNSW ANN algorithm. | `index/chunk.py::split()` token-windows to `chunk_tokens=256`/`overlap=32` (counted via the *embedding model's own tokenizer*, not a generic word count, so chunk sizing matches what's actually embedded), with a boundary guard that pushes a cut point past any open `$$...$$`/`\[...\]` LaTeX block rather than splitting a formula across two chunks (A1's committed "math-aware chunking"). `index/store.py::build()` persists the FAISS index + a `meta.jsonl` chunk sidecar + `index_stats.json`. | Found a real, reproducible crash during testing on this CPU dev machine, precisely diagnosed (not just "flaky"): whenever Nougat's `generate()` actually runs OCR inference and `sentence-transformers.encode()` then runs in that SAME process, it segfaults (5/5 full-pipeline attempts where OCR did real work); when either runs alone in its own process, both are reliable (proven independently: OCR ✓, embed+store+retrieval ✓ on real data). A native CPU MKL/OpenMP vectorization conflict between the two libraries, not a logic bug — mitigations tried (`KMP_DUPLICATE_LIB_OK`, single-threaded MKL/OMP, `batch_size=1`) reduced but did not eliminate it, since `pipeline.py`'s fixed stage order keeps both in one process. Honestly reported as a risk (A2 form Section 5) rather than claimed fixed; the real build runs on Kaggle GPU, where CUDA tensor ops don't hit this CPU-only code path. | Index artifacts live under `data/interim/index/` (gitignored, like `data/raw/`) — rebuilt by `scripts/build_index.sh`, never committed as binaries; `index_stats.json`'s numbers are what the A2 form/notebooks cite, so every reported number traces back to an actual run. | `index_stats.json` records exactly which corpus subset (`dev_max_pages`), which model checkpoints, and when the index was built — a lightweight, code-generated experiment record for this stage. |
